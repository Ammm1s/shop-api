# Shop — фронтенд

Тёмная адаптивная витрина для существующего Spring Boot API. HTML, CSS и JavaScript без зависимостей и сборщика; Node.js используется только для раздачи файлов и проксирования `/api` к Spring. Код остаётся небольшим и доступным для изучения.

## Быстрый запуск

Из папки Shop:

```bash
sh frontend/start.sh
```

Открыть http://localhost:3000. Для обычного запуска нужен Node.js 20+. Скрипт также умеет использовать Node.js, установленный средой Codex на этом Mac.

Бэкенд запускается привычной командой в другом терминале:

```bash
docker compose up --build -d
```

Когда API запущен, нажми «Подключиться снова» на странице или обнови её. Все запросы идут через локальный `/api`; CORS в Java менять не требуется.

## Запуск всего проекта в Docker

Сначала останови локальный frontend с помощью Ctrl+C, если он занимает порт 3000. Из папки Shop:

```bash
docker compose -f compose.yaml -f frontend/compose.frontend.yaml up --build -d
```

Frontend доступен на http://localhost:3000. Контейнер обращается к Spring по адресу `http://app:8080`. Исходный compose.yaml не изменён.

## Что работает

- Каталог с категориями, поиском по названию и описанию, сортировкой и фильтром наличия.
- Карточка товара, корзина, изменение количества и удаление позиций.
- Регистрация, вход через существующий `/auth/login`, профиль и выход.
- Создание заказа, история с пагинацией и отмена новых заказов с подтверждением.
- Панель управления (`/#admin`): создание категорий, создание, редактирование и удаление товаров с подтверждением; поиск и сводка остатков. Доступна для ролей `ADMIN` и `OWNER`.
- Вкладка заказов для `ADMIN` и `OWNER`: список с пагинацией, составом, суммой и статусом; подтверждение переходов `NEW → PAID → SHIPPED`. Для загрузки списка бэкенду нужен `GET /orders/admin` с ответом `Page<OrderResponse>`. Изменение статуса использует `PATCH /orders/{id}/status`.
- Раздел владельца со списком пользователей: `OWNER` может назначить роль `ADMIN` или снять её. Роль владельца защищена от изменения через интерфейс.
- Ошибки валидации, истёкшая сессия, пустые состояния и недоступный API.

JWT хранится в sessionStorage текущей вкладки; пароль не сохраняется. Корзина хранится локально в браузере. Демо-корзина и реальная корзина разделены. Сервер проверяет итоговые цены, остатки и права — интерфейс не заменяет эти проверки. После изменения роли пользователю нужно войти заново: уже выданный JWT действует до завершения своей сессии.

Если API недоступен, включается явно обозначенный демо-каталог. Регистрация, вход и оформление демонстрационных товаров отключены. Фотографии и примерные цены в демо не представляют реальные товары базы. Для настоящих товаров используется необязательная HTTPS-ссылка imageUrl: она задаётся в форме создания или редактирования товара. Картинка отображается в каталоге, карточке и корзине. Пустое поле удаляет ссылку; отсутствие картинки или ошибка загрузки показывает нейтральную иконку. Длина ссылки ограничена 255 символами по текущей схеме базы.

Нет онлайн-оплаты и расчёта доставки. Отметка `PAID` вручную меняет статус только после подтверждения полученной оплаты. Категорию существующего товара изменить нельзя: текущий API обновляет название, описание, цену, остаток и ссылку на изображение. Редактирование и удаление категорий в API отсутствуют. При повторном создании товара с тем же названием бэкенд увеличивает остаток; интерфейс предупреждает и предлагает редактировать существующий товар. Все цены отображаются в рублях; у текущего API нет поля валюты.

## Файлы

- `dist/index.html` — структура страницы и диалоги.
- `dist/style.css` — тёмная тема и адаптивные размеры.
- `dist/admin.js` — управление каталогом, заказами и ролями пользователей.
- `dist/app.js` — запросы API и поведение интерфейса.
- `server.mjs` — HTTP-сервер и прокси с фиксированным адресом API, ограничением размера запросов и тайм-аутом.

Опциональные переменные окружения: `PORT` (по умолчанию 3000), `SHOP_API_URL` (http://127.0.0.1:8080), `HOST` (127.0.0.1). Файл `.env` автоматически не читается. Переменные можно указать перед командой запуска.

Проверка синтаксиса при установленном Node.js:

```bash
npm run check
```
